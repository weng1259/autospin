It contains three obsolete import statements. The `.bak.20260629` suffix means

test. They document or prevent use of the obsolete package rather than depend
on it.

## 7. Remaining blockers

Before deleting `autospin_system/` from the main repository/deployment:

1. archive outside the application tree or explicitly remove
   `tools/ui/emergency_dashboard.py.bak.20260629`;
2. inspect the actual Raspberry Pi systemd unit, `ExecStart`, working directory,
   environment files, process command line, and `PYTHONPATH`;
3. confirm the deployed source/config hashes correspond to the rehearsed code;
4. run the maintained read-only `DeviceRegistry` wiring smoke on the Pi;
5. repeat Web health, registry construction, and dry-run checks on the Pi with
   the obsolete directory absent or inaccessible;
6. preserve an approved source-control tag or external checksum archive;
7. perform deletion as a standalone reviewed change without experiment or
   hardware behavior modifications.

## 8. Is deletion safe?

### Software/code conclusion

**Yes.** The local maintained project, tests, Web service, configured registry,
protocol generation, single dry run, and multi-round dry run all operate with
`autospin_system/` absent. No executable dependency remains in the rehearsed
codebase.

### Production deployment conclusion

**Not yet unconditionally approved.** The source-code dependency risk is
cleared, but actual Raspberry Pi systemd and environment settings remain
unverified, and one dormant ignored backup should be removed from the
application tree. Until those deployment checks pass, deletion from the live Pi
should be treated as conditionally safe rather than fully released.

The main working-tree directory remains untouched after this rehearsal.
