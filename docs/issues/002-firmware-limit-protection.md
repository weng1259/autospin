# Issue #002 — 固件缺少限位保护，连续运动可撞机

**日期**：2026-03-24
**提出人**：Claude（代码审查）
**状态**：resolved（2026-03-24 Phase 2a 固件实现）
**优先级**：高
**类型**：bug
**涉及文件**：`firmware/motor_control/motor_control.ino`, `web_control/index.html`

## 问题描述

当前固件的 `doSteps()` 和连续运动逻辑中 **完全不检查限位传感器**。9 路传感器只用于 150ms 周期上报（`SENS:`），不参与运动决策。

`homing_test.html` 有前端层面的限位处理（检测到限位后发送停止命令），但 `index.html`（主控制面板）没有任何限位逻辑。

这意味着：用户在主面板按住方向键持续运动时，滑块会直接撞到龙门架物理极限，损坏机械结构或传感器。

## 影响

- 滑块撞到行程末端，损坏导轨、传感器支架或电机
- 电机堵转可能触发驱动器过流保护（红灯闪 1 次）
- 闭环模式下位置超差累积，可能需要重新回零校准
- **安全隐患**：Z 轴向下撞机可能损坏工件或旋涂台

## 建议方案

限位保护应在 **固件层** 实现，不依赖上位机——任何上位机（网页、Python、树莓派）都自动受保护。

### 固件改动

在 `doSteps()` 中每批脉冲前检查对应轴的限位传感器：

```
运动方向为正（direction=true）→ 检查正限位传感器
运动方向为负（direction=false）→ 检查负限位传感器
如果触发 → 立即停止该轴，上报 LIMIT:X+（示例）
```

注意：
- 原点传感器不阻止通过（原点在行程中间，正常运动需要经过）
- 限位触发后只禁止继续同方向运动，允许反方向退出
- 可以加一个命令（如 `XO`）临时覆盖限位，用于回零时的退出操作

### 上位机配合

收到 `LIMIT:` 消息后在界面上显示警告，自动停止对应方向的按钮。

## 讨论记录

- 2026-03-24: 代码审查中发现。homing_test.html 有前端限位逻辑，但主面板和固件层都没有。建议在固件层统一实现。

## 验收标准

- [x] 任意轴向正/负方向连续运动时，触碰限位传感器自动停止
- [x] 限位触发后，反方向仍可正常运动（能退出来）
- [x] 限位状态通过串口上报（`@LIMIT X+`、`@FAULT LIMIT_X+`、`@STATE ERROR`）
- [ ] 所有网页面板适配新协议后能正确显示限位状态（待网页迁移）

## 解决记录

- 2026-03-24: 在 Phase 2a 中实现固件层限位保护
- 实现：每批脉冲（10步）前检查运动方向上的限位传感器，触发则立即停止该轴
- 上报：`@LIMIT X+` → `@FAULT LIMIT_X+` → `@STATE ERROR`
- 恢复：`RESET` → `IDLE`，然后可反方向 `JOG` 退出
- 2b 归零中也集成了限位保护：归零方向碰限位自动反弹 50 步后继续寻找原点
