## 问题描述

### 问题 A：回零后未发 HR 命令（原 #008）

回零页面完成三轴回零后不发 `HR` 命令复位坐标，固件内部 position 仍是运动过程中的累计值，逻辑零点和固件零点不一致。

### 问题 B：无两阶段精确回零（Codex #018）

当前回零逻辑：看到原点传感器触发 → 立即停机 → 判定回零成功。撞到负限位时固定反弹 800ms。整个过程没有"快速接近 → 退回 → 慢速二次寻边"的标准流程。

## 影响

- 坐标不复位：后续所有绝对定位偏差
- 无两阶段：原点重复精度受惯性和页面时序影响，不同速度回零结果不同

## 建议方案

### 标准两阶段回零流程

```
Phase 1 — 快速寻找：
  1. 以中速（档位 5）向负方向移动
  2. 检测到原点传感器触发 → 停止

Phase 2 — 退回+慢速精确寻边：
  3. 以低速（档位 2）向正方向退回
  4. 直到原点传感器释放 → 停止
  5. 以最低速（档位 1）向负方向再次接近
  6. 原点传感器再次触发 → 停止 → 此位置为精确零点

Phase 3 — 坐标复位：
  7. 三轴全部完成后发送 HR 命令
  8. 等待固件返回 HOME_RESET 确认
  9. UI 更新为"已回零"状态
```

### 超时与失败处理

- 每个 Phase 设超时（如 30s），超时 → 报错 → 停止
- 限位传感器触发时自动反向退出，不死等
- UI 分别显示"寻找中 / 退回中 / 精确寻边中 / 坐标复位中"

## 验收标准

- [x] 回零流程包含三阶段慢速找边（快寻→退回→慢寻）
- [x] 三轴全部回零后坐标自动归零（position=0），状态进入 READY
- [x] 每阶段有超时保护（快寻 60s，退回/慢寻 30s）
- [ ] 重复回零 5 次，位置偏差 < 0.1mm（待 2e 闭环验证阶段测试）

## 解决记录

- 2026-03-24: 在 Phase 2b 中实现固件层三阶段归零，不再依赖网页端 HR 命令
- 实现：`HOME` 命令触发固件内部三阶段流程（快寻 30μs → 退回 100μs → 慢寻 300μs）
- 归零顺序：Z→X→Y（Z 先归零确保安全高度）
- 支持单轴归零：`HOME X` / `HOME Y` / `HOME Z`
- Z 轴特殊处理：原点在顶部（homeDirectionPositive=true），归零前需释放刹车
- 实测：三轴归零成功，`@HOME_OK` + `POS 0,0,0` + `SENS 010010010`（三原点触发）
