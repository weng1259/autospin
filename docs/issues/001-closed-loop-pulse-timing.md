# Issue #001 — 闭环模式下脉冲时序缺陷导致电机不平稳

**日期**：2026-03-24
**提出人**：Claude（代码审查）
**状态**：obsolete（2026-04-23 —— 自研固件已废弃，grbl-Mega-5X 自带 step generator 无此缺陷；见 ADR-001）
**优先级**：高
**类型**：bug
**涉及文件**：`firmware/motor_control/motor_control.ino`

## 问题描述

切换到闭环模式（SW8=OFF、编码器已接）后，电机运行明显不如开环平稳，有抖动和噪音。

根本原因是固件的脉冲生成方式不满足闭环驱动器的要求。开环模式下驱动器只是"收到脉冲走一步"，对脉冲质量不敏感；闭环模式下驱动器内部有位置环/速度环/电流环三个 PID 在 50μs 周期采样，脉冲间隔的任何抖动都会被放大为机械振动。

具体有以下四个子问题：

### 子问题 A：DIR 建立时间不足

**位置**：`motor_control.ino` 第 73 行

驱动器手册（第 13 页 §5.5）要求 DIR 至少提前 PLS 计数边沿 **6μs** 确定其状态。当前代码在 `digitalWrite(dirPin)` 之后立即开始发脉冲，没有等待。`digitalWrite()` 本身约 4-5μs，第一个脉冲上升沿可能在 DIR 变化后不到 6μs 就到来。

闭环模式下驱动器可能读到错误方向，产生位置偏差突变 → PID 剧烈修正 → 抖动。

### 子问题 B：脉冲循环中的串口检查（最大抖动源）

**位置**：`motor_control.ino` 第 85-90 行

`doSteps()` 在 **每发一个脉冲** 后都调用 `Serial.available()` + `Serial.peek()`，各需 ~2-4μs。这导致实际脉冲周期 = 设定延迟 + 随机的 2~8μs 串口开销。

以速度档 8（目标延迟 50μs）为例，抖动率达 **4-16%**，在高速运动时尤其明显。

### 子问题 C：没有减速——急停导致 PID 震荡

**位置**：`motor_control.ino` 第 107 行、第 173 行

停止方式是直接 `running = false`，脉冲从全速瞬间归零。闭环驱动器检测到"目标突然不动但转子仍有惯性"，PID 会反复过冲/修正，产生停止时的振荡和异响。

当前只有加速逻辑（第 197-208 行），没有对称的减速。

### 子问题 D：运动中 150ms 串口上报造成周期性卡顿

**位置**：`motor_control.ino` 第 212-233 行

每 150ms 输出 `SENS:` + `POS:` + `ALM:` 三行共约 40 字节。115200 baud 发 40 字节 ≈ 3.5ms。Arduino Serial 发送缓冲区仅 64 字节，满时 `Serial.print()` 会阻塞，正好卡在脉冲生成的 `loop()` 中。

表现为每 150ms 出现一次 3-5ms 的脉冲间断，闭环驱动器感知为周期性位置偏差。

## 影响

- 闭环模式下三轴运动有明显振动和噪音
- 高速运动时可能触发驱动器位置超差报警（红灯闪 5 次，P16 阈值）
- 停止瞬间机械冲击，长期影响导轨寿命
- 定位精度下降

## 建议方案

### 方案 A（固件修改）

1. DIR 后加 `delayMicroseconds(10)` — 满足 6μs 建立时间
2. 串口检查从"每步一次"改为"每批 50 步结束后检查一次"
3. 加对称减速：收到停止命令后，逐步升高 `currentDelay` 直到低速再停
4. 运动中暂停或降低上报频率（改为 500ms，或运动中只报 POS 不报 SENS/ALM）

### 方案 B（驱动器拨码，配合方案 A）

- **SW7 → ON**：开启驱动器指令平滑功能，内部滤波补偿脉冲抖动

### 方案 C（驱动器参数调整，需要 HISU 软件 + TTL-USB）

通过 J3 串口连接 HISU 调参软件，调整 PID 参数：
- P4（位置环比例）：2000 → 800~1200
- P5（位置环积分）：200 → 50~100
- P19（指令平滑系数）：2 → 4~6
- P22（脉冲滤波）：3 → 5~8

## 讨论记录

- 2026-03-24: 代码审查中发现，用户反馈闭环后运行不如开环平稳。分析固件后确认脉冲时序是根本原因。建议先做方案 A + B（无需额外硬件），效果不够再做方案 C。
