# Issue #007 — 连续运动中降速命令不生效

**日期**：2026-03-24
**提出人**：Codex（代码审查）
**状态**：obsolete（2026-04-23 —— 自研固件已废弃，grbl `$J=` + feed-override 官方机制替代；见 ADR-001）
**优先级**：高
**类型**：bug
**涉及文件**：`firmware/motor_control/motor_control.ino`

## 问题描述

速度命令（`X1~X9` 等）只更新 `stepDelay`，而连续运动时只在 `currentDelay > stepDelay` 才做收敛。运行中从快档切慢档时，`currentDelay` 小于新 `stepDelay`，不会回升到更慢延时。

结果是“界面显示已降速，但电机实际仍按旧速度运行”。

## 影响

- 临近限位时用户尝试降速无效，增加撞机风险
- 速度控制反馈与实际行为不一致，影响调试和操作信任

## 建议方案

- 将速度收敛改为双向：`currentDelay > stepDelay` 时减小，`currentDelay < stepDelay` 时增大
- 收到速度命令后，若轴处于 `running=true`，立即进入新目标速度收敛
- 上报当前生效速度（或延时）用于前端校验

## 讨论记录

- 2026-03-24：代码路径分析确认仅支持“向快收敛”，不支持“向慢收敛”。

## 验收标准

- [ ] 连续运行中从 8 档切到 2 档后，速度可在可预期时间内明显下降
- [ ] 连续运行中升速和降速都可平滑生效
- [ ] 前端显示速度与实际运动速度一致
