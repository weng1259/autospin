# Issue #013 — 波特率扫描后恢复连接流程存在端口状态错误

**日期**：2026-03-24
**提出人**：Codex（代码审查）
**状态**：open
**优先级**：中
**类型**：bug
**涉及文件**：`web_control/gripper.html`

## 问题描述

扫描流程每轮会 `close/open` 端口，扫描结束后又直接 `port.open(currentBaud)` 恢复。末轮结束时端口通常已打开，再次 `open` 容易失败；同时临时 reader/writer/pipe 链路未统一回收，易造成后续状态混乱。

## 影响

- 扫描结束后出现“恢复连接失败”
- 面板进入半连接状态，后续发送/读取异常

## 建议方案

- 封装统一 `reopenPort(baud)`：`cancel reader -> release writer -> close -> open -> rebuild IO`
- 禁止在多个路径重复建立 `pipeTo` 链路
- 扫描成功/失败后都走同一恢复路径

## 讨论记录

- 2026-03-24：审查时发现恢复阶段未校验“端口是否已打开”。

## 验收标准

- [ ] 波特率扫描后始终能恢复到用户选定波特率
- [ ] 扫描流程可连续运行 5 次不出现恢复失败
- [ ] 扫描前后发送与读取功能均正常
