# Issue #015 — 未利用 ENA 输入构建硬件级急停链路

**日期**：2026-03-24
**提出人**：Codex（代码审查）
**状态**：open
**优先级**：中
**类型**：安全
**涉及文件**：`firmware/motor_control/motor_control.ino`, `docs/architecture.md`, `hardware/龙门架/驱动器/2HSS57-C-用户手册.md`

## 问题描述

驱动器提供 ENA 输入用于使能控制，但当前系统仅依赖串口 `S` 命令软件停机，未建立独立硬件断使能路径。浏览器卡死、USB 异常或固件跑飞时，缺少失效安全手段。

这是“控制与安全同源”的架构缺口。

## 影响

- 极端故障下无法保证立即去扭矩
- 急停链路可靠性依赖软件状态，不满足硬件优先原则

## 建议方案

- 将三轴 ENA 纳入硬件急停回路（急停按钮/安全继电器统一切断）
- 固件增加 ENA 状态上报与上电自检提示
- 文档补充 ENA 接线与故障演练流程

## 讨论记录

- 2026-03-24：对照驱动器手册时确认 ENA 能力尚未纳入当前架构。

## 验收标准

- [ ] 急停触发后无需串口命令即可断使能
- [ ] 任意上位机故障时，硬件急停仍可独立生效
- [ ] 文档包含 ENA 接线和测试步骤
