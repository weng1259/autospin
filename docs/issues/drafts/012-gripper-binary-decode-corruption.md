# Issue #012 — 二进制串口数据被文本解码/再编码污染

**日期**：2026-03-24
**提出人**：Codex（代码审查）
**状态**：open
**优先级**：中
**类型**：bug
**涉及文件**：`web_control/gripper.html`

## 问题描述

读取流程使用 `TextDecoderStream` 获取字符串，再用 `TextEncoder` 回写为字节存入 `readBuffer`。对于 Modbus/私有二进制协议，非文本字节会被替换或重编码，导致原始帧失真。

后续探测判断依赖 `readBuffer`，因此判断依据不可靠。

## 影响

- 可能误判“有无回复”或错误解释回复内容
- CRC/帧长分析不可用，协议定位效率显著下降

## 建议方案

- 读取层直接用 `port.readable.getReader()` 处理 `Uint8Array`
- 保留原始字节缓冲用于探测与校验
- 日志层单独生成 ASCII/HEX 展示，不反向写入原始缓冲

## 讨论记录

- 2026-03-24：审查发现读链路以文本为中心，和二进制探测目标冲突。

## 验收标准
