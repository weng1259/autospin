# Issue #016 — 命令解析存在阻塞等待，异常字节会造成运动顿挫

**日期**：2026-03-24
**提出人**：Codex（代码审查）
**状态**：obsolete（2026-04-23 —— 自研固件已废弃，grbl 处理命令解析；见 ADR-001）
**优先级**：中
**类型**：优化
**涉及文件**：`firmware/motor_control/motor_control.ino`

## 问题描述

固件在读取到首字符后使用 `while (!Serial.available())` 最长阻塞 100ms 等待第二字符。若出现串口丢字节、噪声或截断命令，主循环会在等待期间停止正常调度。

该阻塞路径与运动循环共享主线程，容易形成可感知停顿。

## 影响

- 连续运动中偶发卡顿
- 串口异常时系统响应变慢，影响控制稳定性

## 建议方案

- 改为非阻塞状态机解析（有限状态 + 超时丢帧）
- 避免任何 `while` 忙等阻塞主循环
- 对非法命令做统一丢弃与错误上报

## 讨论记录

- 2026-03-24：代码审查识别出两处 100ms 等待路径。

## 验收标准

- [ ] 异常/残缺命令不会阻塞运动循环
- [ ] 连续运行期间串口噪声注入不再导致明显停顿
- [ ] 非法命令有明确错误反馈
