# Issue #011 — 夹爪开/闭/停按钮仍为占位实现

**日期**：2026-03-24
**提出人**：Codex（代码审查）
**状态**：open
**优先级**：高
**类型**：功能
**涉及文件**：`web_control/gripper.html`

## 问题描述

`gripperOpen()`、`gripperClose()`、`gripperStop()` 目前仅记录日志并更新 UI 动画，未发送任何实际控制协议帧。页面会给出“动作已执行”的视觉反馈，但设备侧不一定发生动作。

这是典型“仿真状态冒充实控状态”问题。

## 影响

- 联调时误判功能已打通，延迟暴露真实协议问题
- 操作人员对系统状态判断错误，带来流程风险

## 建议方案

- 未绑定真实协议前，禁用控制按钮并标注“仅仿真”
- 绑定后把开/闭/停改为实际帧发送，加入应答与超时处理
- UI 状态只根据设备反馈更新，不根据本地假设更新

## 讨论记录

- 2026-03-24：审查时确认三处函数内存在“待绑定实际协议指令”注释。

## 验收标准

- [ ] 开/闭/停按钮能发送真实协议帧
- [ ] 无反馈时 UI 不显示成功动作
- [ ] 日志中可看到发送帧与应答帧对应关系
