### 项目概况

**智能旋涂仪**：华南理工大学实验室项目，基于 GH40 龙门架三轴运动平台，目标是实现自动化旋涂工艺。

硬件配置：
- 龙门架 GH40-D75-X300S-Y300S-Z100S-57（行程 300×300×100mm）
- 57 闭环步进电机 × 3（1000 线编码器，Z 轴带电磁刹车）
- 杰美康 2HSS57-C 驱动器 × 3（当前闭环模式 SW8=OFF）
- DS-ES61 槽型光电传感器 × 9（每轴：负限位/原点/正限位）
- Arduino Mega 2560 下位机（GPIO 脉冲/方向控制）
- DSTUR-T80 USB 继电器 8 路（CH1 夹爪、CH2 Z 轴刹车）
- 24V 15A 开关电源

目标架构（尚未完全实现）：
```
用户设备（Mac/手机）→ WiFi → 树莓派上位机
  ├── USB 串口 → Arduino（脉冲/方向 + 传感器）
  ├── USB 串口 → DSTUR-T80 继电器（刹车/夹爪通断）
  └── USB 转 RS485 → 旋涂模块 + 移液模块（待采购）
```

当前阶段：硬件接线基本完成，闭环刚启用，正在调试运动质量。还没开始做自动化流程。

### 审查维度

请从以下 **所有维度** 审查，每个发现独立写一条 issue：

#### A. 代码质量（bug、正确性、健壮性）
- 逻辑错误、边界情况、异常处理
- 时序是否满足硬件手册要求
- 串口断开、传感器故障等异常场景

#### B. 安全性
- 撞机、堵转、触电、器件损坏风险
- 急停链路可靠性
- 失效安全设计（断电、通信中断时的行为）

#### C. 架构与设计
- 上下位机职责划分是否合理
- 固件命令协议是否足够（是否需要扩展？比如绝对定位、坐标保存等）
- Web Serial 是否是最终方案？树莓派迁移路径是否清晰？
- 代码复用：四个网页面板有大量重复代码（连接逻辑、样式），是否需要抽取公共模块？

#### D. 功能缺失（Feature Request）
- 对比项目目标（自动化旋涂），当前缺少哪些关键功能？
- 是否需要：坐标系统（工件坐标/机器坐标切换）、示教功能（记录位置点）、运动队列（G-code 或类似协议）、安全围栏（软限位）？
- 自动化流程编排需要什么基础设施？
- 数据记录和回放（实验参数记录、操作日志持久化）
- 多用户/多实验配置管理

#### E. 用户体验
- 网页面板操作是否直观？移动端是否好用？
- 错误信息是否清晰？操作是否有足够的反馈？
- 组员（非技术背景）能否顺利使用？
- 是否需要操作引导或新手教程？

#### F. 开发流程与工程实践
- 目录结构是否合理？是否需要调整？
- 是否需要版本管理（git）？当前没有 .git
- 是否需要自动化测试（至少固件的单元测试）？
- 固件上传流程是否可以简化？
- 文档是否完整？新组员能否靠文档独立上手？

#### G. 可扩展性与未来规划
- RS485 旋涂/移液模块接入的准备工作
- 树莓派迁移需要改什么？
- 如果未来要加第四轴或更多设备，架构是否支持？
